# 🛠️ Lab 8: The Bulletproof Data Engine (Validation & Data Wrangling)

## Concepts to Practice
* Complex Data Types (`object`)
* Input Variable Validation
* Safe Looping (`for_each` & `toset()`)
* Custom Conditions (`precondition`)
* Dictionary Outputs (`for` expressions)

---

## Objective
Build a module that provisions a team of IAM users. You will enforce strict naming conventions using variable validation, ensure the environment is safe using preconditions, and finally, extract the generated AWS ARNs into a clean, queryable dictionary.

---

## The Requirements

### 1. The Complex, Validated Variable
Create an `object` variable that accepts a team name and a list of developer usernames. 
* Add a `validation` block to ensure the `team_name` starts with `"dev-"` (input variable validation).

### 2. The Resource & Precondition
Use `for_each` to safely create AWS IAM users based on the list of developers (remember to convert the list to a set!).
* Add a `lifecycle` block with a `precondition` that ensures the list of developers has at least 2 people in it before Terraform even attempts to call the AWS API.

### 3. The Dictionary Output
Create an `output` block that uses a `for` expression to iterate over the generated resources and map the IAM user names directly to their generated ARNs.

---

## Execution & Testing Steps

#### Phase 1: Successful Deployment
1. Run `terraform apply -auto-approve` and inspect the `developer_arns` output dictionary. Notice how cleanly the names map to the ARNs.

#### Phase 2: Triggering the Validation Guardrail
1. Change the `default` team name in your variable to `"ops-backend"`.
2. Run `terraform plan`. 
3. Terraform will block the execution and return your custom Security Policy error message, preventing bad naming conventions from reaching AWS.

#### Phase 3: Triggering the Precondition Guardrail
1. Revert the team name back to `"dev-backend"`.
2. Change the `developers` list to only have one name (e.g., `["alice"]`).
3. Run `terraform plan`. 
4. The lifecycle hook will catch the configuration flaw and block the deployment, enforcing your redundancy rule.

---

## Terraform Code (`lab_8.tf`)

```hcl
provider "aws" {
  region = "us-east-1"
}

# 1. Complex Variable with Validation
variable "team_config" {
  type = object({
    team_name  = string
    developers = list(string)
  })
  
  default = {
    team_name  = "dev-backend"
    developers = ["alice", "bob", "charlie"]
  }

  validation {
    condition     = substr(var.team_config.team_name, 0, 4) == "dev-"
    error_message = "Security Policy: The team_name must begin with 'dev-'."
  }
}

# 2. Resource with Precondition and for_each
resource "aws_iam_user" "team" {
  # Convert the list to a set to safely use for_each
  for_each = toset(var.team_config.developers)
  name     = "${var.team_config.team_name}-${each.key}"

  lifecycle {
    precondition {
      condition     = length(var.team_config.developers) >= 2
      error_message = "A team must have at least 2 developers to ensure redundancy."
    }
  }
}

# 3. Data Extraction (The elegant way with for expressions)
output "developer_arns" {
  description = "A mapped dictionary of IAM Usernames to their AWS ARNs"
  # Iterate directly over the map generated by for_each
  value = {
    for user in aws_iam_user.team : user.name => user.arn
  }
}
```
